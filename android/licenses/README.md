# Android dependency notices

`dependencies.json` records the reviewed license, source location and SHA-256 for each external Gradle runtime artifact. It covers the union of the current debug/release variants, including transitive libraries. Metadata-only platforms/BOMs and build plugins are not application artifacts. `licenses.gradle` resolves the selected variant and runs `../scripts/android-license-report.py` without downloading license text or compiling Gecko. The packaged report contains only that variant's actual artifacts, the required license texts and license/NOTICE files found in the original JAR/AAR entries (including nested `classes.jar` and `libs/*.jar`). Identical notice text is shared without dropping its origins.

Run `:navis:generateDebugNavisLicenses` or `:navis:generateReleaseNavisLicenses` in the prepared Gecko Gradle workspace to inspect notices without assembling the application. Normal asset merging depends on this verification. The resolved artifact set must exactly match the reviewed variant, so omitted as well as added dependencies fail the task. A changed hash, absent license or changed license text also fails. Upgrades require reviewing the new artifact, its Maven POM (including inherited licenses), upstream source and applicable supplemental notices; do not copy an old license assumption to a new dependency merely to unblock a build. Add a reviewed `additional_notices` file when required notices are absent from the published artifact. Preserve upstream legal text rather than applying prose formatting to it.

The generated `assets/navis-licenses/android-dependencies.txt` is consumed by the existing Runtime credits reader and is available offline. The adjacent JSON identifies the selected artifacts and report hash. Package verification checks both against the source policy. Gecko's native closure and application-bundled extensions retain their separate source/license inventories; this report does not replace them or certify a complete binary release.
